INTAKE RACK MOTOR HARDWARE TEST
Branch base: frc6560/Robot-Code-2026 tidle_tumble (51123e0)
This replaces the earlier full-intake implementation and test procedure.

BEHAVIOR
On each teleop enable, the X44 rack motor is commanded to full extension.
After 3 seconds from enable, it is commanded back to zero and held retracted.
It does not continuously cycle. Disable/re-enable teleop to repeat.
Disabled, autonomous and Test modes stop this rack motor.
Legacy intake/outtake buttons and shooting oscillation do not control the rack.
The roller controller is not instantiated or driven. No roller is required.
Other existing drivetrain/shooter/indexer controls remain as on tidle_tumble.

STARTUP ASSUMPTION
Physically fully retract the rack BEFORE starting/restarting robot code.
The controller's position is automatically set to zero at code startup.
There is no dashboard homing action or automatic search for a physical home.
Disabling/re-enabling does not re-zero the encoder; it repeats the timed cycle.
If the rack controller resets, physically retract and restart code.
Feedback/configuration errors stop motor output. Fix startup configuration
errors and restart code to reapply configuration.
Do not restart code with the rack extended: that would assign a false zero.

CONFIGURATION
Rack X44: rio CAN ID 24. There is no intake roller controller in this test.
Do not change to Canivore ID 24: that address is already used by the shooter.
Existing configured swerve and mechanism CAN addresses pass the collision test.
Rack reduction: 64/14; pinion diameter: 1.751 inches; travel: 11 inches.
Extension target: about 9.14 motor rotations; retracted target: 0.
Motor inversion remains false, as specified by the original branch.
Motion Magic cruise: 5.5 motor rotations/second; acceleration: 50 rotations/s^2.
Position kP: 0.5; velocity feedforward kV: 0.12; normal neutral mode: brake.
Supply/stator limits: 30/40 A. Encoder-based software limits remain enabled.
DEPLOY_TEST_EXTEND_SECONDS in Constants.java sets the 3-second extension time.
Three seconds includes travel time; retraction begins at that time even if
the rack has not reached full extension. Physical travel and direction must
agree with these inherited values for the hardware test to behave correctly.

TEST
1. Fully retract the rack, then deploy/start the code. Keep its path clear.
2. Check Intake/DeployConnected, Intake/Ready and configuration/zero status.
3. Enable TELEOP: rack should extend immediately.
4. At 3 seconds, rack should retract and remain there.
5. Disable at any time to stop output. Re-enable teleop to run the cycle again.
6. Confirm actual travel, direction, current and applied voltage. If motion is
   reversed or the rack contacts a hard stop, disable and correct the settings.
Dashboard: Intake/DeployPositionRotations, Intake/DeployTargetRotations,
Intake/DeployConnected, Intake/Ready, Intake/DeployConfigurationStatus,
Intake/ZeroStatus. Current/voltage/temperature are recorded in Intake logs.

VALIDATION
Java 17 / WPILib 2026.2.1 / Phoenix 6 26.1.2.
Tests cover teleop timing, one cycle then hold, repeat after re-enable, stop
on disable/non-teleop/fault/coast, and immunity to old intake/shot commands.
Existing shooter/indexer/driver tests and configured CAN address checks remain.
No hardware deployment or physical verification was performed.
